# 确定性的编排外壳 + 只承载动态决策的规划图

把会话、路由、幂等、超时重试、预算守卫、版本与审计这些控制逻辑放进图里，会得到两个后果：控制逻辑无法单测，动态决策被控制复杂度淹没。同时，业界实践（以及框架官方「从最简方案起步、只在能证明收益时才增加复杂度」的立场）都指向同一个形态：**外层状态机 + 内层图编排**。

我们决定：控制流用普通代码实现，可单测、可审计、可恢复；只有真正需要运行时判断的部分（候选构建、归属草拟、求解与修复循环、解说）进入规划图。图编排框架因此在本项目里是骨架中的一个零件，而不是应用的骨架。

## 影响

- 外壳的每个职责都有不联网、不启动模型的单元测试；这是 CI 能跑得快的前提。
- 「为什么这次走了这条路」可审计——路由是规则，不是模型输出。
- 新增能力时先问「它是确定性的还是动态的」，这成为本项目的架构语言。
- 代价：需要维护两层之间的接口契约（状态如何进出图、中断点如何持久化）。这是明确的、一次性的成本。
