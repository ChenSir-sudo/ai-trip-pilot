# 数据访问做两个实现，且永不落库真实接口数据

地图服务中国站协议（[原文](https://developer.amap.com/pages/terms/)，更新 2025-12-03，已核一手条文）**明文禁止**在平台外存储或缓存其内容。第 3.5 条原文：「您只可使用在平台网站相应官方文档中所列明和开放的本服务的功能来对相关服务数据的结果进行展示，但是您**不得直接存储、缓存或技术手段抓取、使用本服务内部数据、图片等相关内容**」——即**展示允许、存储禁止**。第 3.4 条另禁止「用于模型或算法训练及相关数据集构建」；第 4.6 条规定与服务方交互产生的数据归服务方所有。

这意味着**真实接口不能作为开发与评测的数据来源**。理由不是慢或贵——个人认证开发者的基础搜索服务为 5,000 次/月，超限仅 30 元/万次——而是因为：**用真实接口跑出来的结果不许留存，就构不成可复现的回归集**，且协议连「构建数据集」本身都明文禁止。此外第 3.6 条规定服务「原则上仅限于您自己使用」，把服务交由第三方实际使用需事先告知并获认可。

我们决定把数据访问收敛到一组接口（地点检索、地名解析、路径、天气、班次、区域查询），提供两个实现：**真实实现**（地图服务官方 MCP + 社区只读票务接口）用于演示与抽样验证；**离线实现**（许可明确的开源数据集 + 免费天气 + 距离估算）用于开发、回归评测、CI 与断网演示。靠环境变量切换。

## 影响

- 离线实现从「降级方案」升级为**架构主路径**：评测必须跑在它上面才可复现、不违约。
- 两条路径共用同一组接口，因此**评测结果与演示行为走同一条代码路径**，评测才有代表性。
- 离线语料只允许放许可明确的数据集，且与真实接口数据物理上不混存——这同时落实了产品红线「事实通道与知识通道互不混存」。
- 演示前无法靠「预热缓存」来省配额（缓存本身违约），只能靠缩小候选池与减少检索次数，这反过来强化了求解器方案（小候选池正是求解器的理想输入）。
- 「原则上仅限于您自己使用」直接决定了**不公网部署**：演示靠录屏与本地一键运行，而非开放访问。这一条把产品决策与合规事实绑定在一起。
- 配额压力比预想小（搜索 5,000 次/月，超限 30 元/万次），因此**约束来自条款而非额度**。对外讲述时必须说准这一点，否则就是把困难夸大了——而夸大的困难经不起追问。
